## 50. グランドルール：右下スタックの要素に固定`height`を使わない（必須・v3.95・2026-08-21）

### v3.94の2-2判断が見落としていたこと

v3.94の2-2は「FAB/ショートカット/Toastは既に`bottomStack.ts`の定数と一致する明示`height`を持っているのでResizeObserverは無意味」と判断して(c)（クリアランスを少し増やすだけ）を選んだ。**この判断は循環していた**：定数と一致する`height`を持っているのは、定数を`height`としてそのまま使う設計にしたからであり、**その固定`height`自体が「人による設定への弱さ」の原因**だった。v3.94の報告書は「min-font-sizeが固定高さの箱の内容をあふれさせる」ことを正しく認識していながら、「検出できない」と書いただけで直していなかった。

固定`height`は、v3.91の「見積もり値のハードコード」・v3.91〜v3.94の「定数どうしの検算しかしないテスト」に続く、**同じ論点が3回すり抜けた3つ目の形**だった：
1. v3.91：見積もり値をハードコードして少し足すだけの対応
2. v3.91〜v3.94：`bottomStack.test.ts`が定数どうしの整合性しか検査せず、実物とのズレを検知できない
3. v3.94：固定`height`そのものが「人による設定で中身が切れる」原因だと認識しながら、「検出できない」とだけ書いて放置した

固定`height`は「ズレ」（要素どうしが重なる）ではなく、**「切れ」**（要素の中身が箱に収まらずクリップされる）という別の症状で同じ根本原因（拡大率・最小フォントサイズ設定・OSの表示スケールに弱い数値のハードコード）を再現する。**そして「切れ」はv3.91〜v3.94の重なり検査（`bottomStack.test.ts`・`devOverlapCheck.ts`）では原理的に検出できない**（重なり検査は「2つの要素が同じ場所にいるか」しか見ないため、1つの要素の中身がその箱からあふれているだけの状態は対象外）。

### 対応（v3.95）

- **文字を含む右下スタックの要素は、固定`height`をやめて`minHeight`にした。** 対象：`TaskSidePanel`のフッター（`SIDE_PANEL_FOOTER_MIN_HEIGHT_PX`）・ショートカットボタン（`SHORTCUTS_BUTTON_MIN_HEIGHT_PX`）・Toastの各項目（`TOAST_ITEM_MIN_HEIGHT_PX`）・モバイルのボトムナビ（`BOTTOM_NAV_MIN_HEIGHT_MOBILE_PX`）・FAB展開メニューの3項目（`FAB_MENU_ITEM_MIN_HEIGHT_PC_PX`/`_MOBILE_PX`）。**FAB本体（＋アイコンのみの48×48固定正円）は文字を含まないため対象外**（固定サイズのまま）。定数名に`MIN_`を付け、「最低保証の高さ」であることを明示した。
- **残る「本当の縦の依存」を洗い出した結果、統括の整理どおり2つで正しかった**（詳細はSection内の実装報告参照）。FAB本体・ショートカットボタン（通常時）・Toastの`bottom`は、この2つの実測値から`bottomStack.ts`の純粋関数（`computeFabBottomMobile`・`computeFabMenuTop`・`computeAboveFabBottom`等）で導出する設計にし、`src/stores/uiLayoutStore.ts`に`mobileBottomNavHeightPx`/`fabMenuHeightPx`を追加、測る側（`MainLayout.tsx`・`QuickAddFab.tsx`）が`ResizeObserver`で書き込む。
- **`devOverlapCheck.ts`に「あふれ検出」を追加した。** `data-bottom-stack`属性を持つ各要素の`scrollHeight > clientHeight`を見て、はみ出していれば要素名・不足px数を`console.warn`する（重なり検出とは独立の別チェック）。同じ問題を毎ポーリングごとに連呼しないよう、警告済みキーを保持し解消されたら削除する（再発したら再度警告する）。

### 再発防止：新しいグランドルール

**右下（PC）・画面下端（モバイル）に積み上がる要素で、文字（ラベル・メッセージ等）を含むものには、固定`height`を使わないこと。** `minHeight`にし、対応する定数には`MIN_`を付けて「最低保証の高さ」であることを明示する。固定サイズで良いのは、アイコンのみ・文字を一切含まない要素（FAB本体等）に限る。

理由：固定`height`は拡大率・最小フォントサイズ設定・OSの表示スケール次第で「ズレ」ではなく**「中身が切れる」**という形で同じ根本原因の問題を再現し、かつ重なり検査（`bottomStack.test.ts`・`devOverlapCheck.ts`の重なり検出）では原理的に検出できない。この論点はv3.91→v3.94の3回にわたってすり抜けた（本Section冒頭参照）ため、同じ判断ミスを繰り返しやすい箇所として明記しておく。
