## 43. タスク追加「＋」FABの共通化（v3.86）＋右下スタックの一元管理（v3.91・v3.92で不変条件を是正・2026-08-21）

### v3.86：共通コンポーネント化（維持）

クレーム「タスク追加のプラスボタンが、メニュー表示などで何らかのテキストと被り、プラスマークより下のレイヤーの表示が見えない」への対応として、PC版・モバイル版で完全に別のJSXとして重複実装されていたFAB本体・展開メニュー（旧`MainLayout.tsx`）を`src/components/layout/QuickAddFab.tsx`に切り出した。座標・展開メニューの起点（PC＝AI相談パネル幅ぶん動く／モバイル＝固定）は`isMobile`propと`isConsultOpen`/`consultPanelWidth`/`isConsultResizing`propで受ける。**この共通化はv3.91でも維持している**（山本さんが差し戻しを求めたのは次項の「収納・半透明」であって、コンポーネント統合ではない）。`data-tour-id="fab"`（将来のツアーが参照する可能性がある予約属性）はPC側のみ維持している。

### v3.91：v3.86の「待機中は右端へ半分収納＋半透明にする」を撤去

**クレーム（利用者の意見）**：①保存ボタンと＋ボタンが被っている（タスクのサイドパネルを開いた状態で、フッターの「保存」ボタンの上に＋ボタンが重なっていた）。②＋ボタンの位置と透明度は元に戻してほしい（＝v3.86で入れた「右端へ半分収納」「待機中は半透明」をやめる）。③その上で、＋ボタンが「削除」「保存」ボタンのあるゾーンに被らないよう、少し上へずらす。④その際、ショートカットボタンと被らないように気をつける。

- `QuickAddFab.tsx`から、収納・半透明に関わる全て（`FAB_IDLE_OPACITY`/`FAB_IDLE_TRANSLATE_X`/`FAB_NEAR_RADIUS_PX`の3定数、`pointermove`リスナー・`isNear`/`isFocused`state・`useHoverCapable()`・`usePrefersReducedMotion()`の2フック・収納時のtransform/opacity分岐）を削除した。待機中も常に不透明度1・オフセット0で表示する。
- タッチ端末向けの分岐（hoverできない環境では収納しない）も、収納自体が無くなったため不要になり削除した。
- FABの◇マーク開閉時の回転（`isFabMenuOpen`のとき`rotate(45deg)`）はv3.86の収納・半透明とは別機能（＋を✕に見せる演出）のため維持した。

### v3.91：右下に積み上がる要素のスタックを一元管理する（`src/lib/layout/bottomStack.ts`。旧`fabLayout.ts`から改名）

**根本原因**：v3.86〜v3.90時点は「TaskSidePanelのフッター（削除／保存ボタン）」「FAB」「ショートカットボタン」「Toast」がそれぞれ独立に自分のbottom値を手書きしており、片方を動かすたびに別のものと当たっていた。統括が確認したところ、v3.90時点で以下の重なりが実際に存在した：
- **PC・通常時**：TaskSidePanelフッター（bottom 0〜約40px）とFAB（bottom 24〜72px）が24〜40pxの範囲で重なる（今回のクレーム①の実体）。
- **PC・通常時**：ショートカットボタン（bottom 100〜128px）とToast（bottom 84〜120px）も100〜120pxの範囲で重なっていた（クレームには無かったが横断確認で発覚）。
- **モバイル・通常時**：ショートカットボタン（bottom 128px）とToast（bottom 128px）がbottom同値で完全に重なっていた。

この3件は、修正前に実際にテスト（後述）で検出できることを確認済み（詳細はテストの節を参照）。

**設計**：「画面右下（PC）／画面下端（モバイル）に積み上がる要素のスタック」を`src/lib/layout/bottomStack.ts`に定義した。積み順（下から上）は次のとおり：

```
PC     ：TaskSidePanelフッター → FAB（→展開時はFAB展開メニュー） → ショートカットボタン → Toast
モバイル：ボトムナビ            → FAB（→展開時はFAB展開メニュー） → ショートカットボタン → Toast
```

各要素の`bottom`は「1つ下の要素の`bottom` + 高さ + クリアランス（`STACK_CLEARANCE_PX`=12px）」の式で算出し、手書きの数値を並べない。高さが必要な要素（TaskSidePanelのフッター・ショートカットボタン・Toast本体・FAB展開メニュー項目）は、対応するコンポーネント側もこの定数を明示`height`として使う（`TaskSidePanel.tsx`のフッター・`MainLayout.tsx`のショートカットボタン・`Toast.tsx`のトースト本体・`QuickAddFab.tsx`のモバイル版メニュー項目）。**これにより、フッターの padding やボタンサイズを変えたら FAB の位置が自動で追随する**（高さの見積もりとレイアウト実体が同じ定数を参照するため、乖離が起きない）。

主な値（v3.92・2026-08-21時点）：

| 要素 | PC bottom | モバイル bottom | 高さ |
|---|---|---|---|
| TaskSidePanelフッター（PCのみ） | 0 | — | 40px |
| ボトムナビ（モバイルのみ） | — | 0 | 56px |
| FAB本体 | 52px（40+12） | 68px（56+12・旧値と同じ） | 48px |
| FAB展開メニュー（3項目） | 102px（52+48+2） | 118px（68+48+2） | 126px／136px |
| ショートカットボタン（通常時） | 112px（52+48+12） | 128px（68+48+12・旧値と同じ） | 28px |
| ショートカットボタン（FAB展開時） | 240px | 266px | 28px |
| Toast | 112px（52+48+12） | 128px（68+48+12） | 40px |

**FABの上げ幅（クレーム③）**：「サイドパネルのフッターの上端＋クリアランス」に置く（52px＝フッター高さ40px＋クリアランス12px）。旧位置（24px）からの上げ幅は28pxで、フッターを避けられる最小限に留めた（必要以上に上げると画面中央寄りに浮いて目立つため）。**PC側は「TaskSidePanelが実際に開いているかどうか」に関わらず常にこの位置にする**（開閉のたびにFABの位置が動くとちらつく・「開いた瞬間だけ重なる隙」が生まれるため）。TaskSidePanelはPC・タブレット専用でモバイルには出ない（`TaskSidePanel.tsx`冒頭コメント。モバイルの編集はTaskEditModal＝中央寄せの全画面モーダルで、この右下スタックには参加しない）ため、モバイル側のFAB位置は変更していない（旧68pxのまま＝ボトムナビの上端+クリアランス）。

**ショートカットボタン・Toastの退避（クレーム④）**：ショートカットボタンはFAB本体の上端+クリアランスに置き、FABメニュー展開時はメニューの上端+クリアランスまで押し上げる（旧仕様と同じ考え方・数値だけ追随）。

**🔴 v3.91→v3.92：Toastの位置を「FABの真上まで」に是正した（このスタックが守るべき不変条件の再定義）。** v3.91は「ショートカットボタンが最も高くなるFABメニュー展開時」を基準にToastを常に静的確保する設計にしており、その結果Toastの通常位置がv3.90時点（84px）から280px（画面の下から約1/3）まで押し上げられていた。「どの2つも重ならない」という不変条件を、重なっても実害の無いペアにまで一律に適用したことが原因（統括の指摘）。

このスタックが本当に守るべき不変条件は**「操作を妨げないこと」であって「一切重ならないこと」ではない**。要素は次の2種に分かれる：
- **FAB（と、その展開メニュー3項目）**：利用者が押したい主要な操作ボタン。隠してはいけない。
- **ショートカットボタン**：常設だが補助的なaffordance。数秒間Toastに隠れても実害が無い（通知が消えれば元に戻る）。

Toastはz-index最前面に出るうえ数秒で自動消去される一過性の表示のため、「FABを隠さない」ことだけを守り、「ショートカットボタンと重ならない」ことまでは要求しない。v3.92でToastを`FAB_BOTTOM_*_PX + FAB_SIZE_PX + STACK_CLEARANCE_PX`（＝ショートカットボタンの通常位置と同じ式）に変更し、**Toast⇔ショートカットボタンの重なりは意図した許容**として`bottomStack.test.ts`の`ALLOWED_OVERLAPS`に理由付きで登録した。ToastはFABメニュー開閉によらず静的な位置のままのため、**FABメニュー展開時はToast⇔FAB展開メニューも重なりうる**（同じ理由＝メニュー項目はクリック直後にメニュー自体を閉じてから処理を実行するため、あるアクション結果のToastとそのFABメニューが同時に開いたまま重なることは通常起きない）。これも`ALLOWED_OVERLAPS`に登録した。**Toast⇔FAB本体（利用者が押したい主要な操作ボタン）は重ならないことを維持している**（Toastの位置自体がFABの真上＝FAB本体の上端+クリアランスのため、構造的に重ならない）。

**AI相談パネルが開いているときの`right`の避け方（`consultPanelWidth + 24`）は現状の挙動を維持**した（変更していない）。

### `TaskSidePanel`のフッター高さを明示`height`にした

フッター（🗑削除／保存ボタン）のdivに`height: ${SIDE_PANEL_FOOTER_HEIGHT_PX}px`（40px）を明示した。従来は`padding`とボタンサイズによる自然な高さ（実測約37〜38px）に任せていたが、明示することで「フッターの見た目＝FABが避けるべき高さ」を1つの数値に固定した（見た目上の差は数px以内で、現状の見た目を変えない）。

### ErrorBarとの関係（v3.86からの記録・v3.92で再確認・変更なし）

「履歴N件」バッジ単体（エラー表示が無い状態）はFABと数px〜十数pxの隙間があり、通常は重ならない。エラー行が複数（最大5件）積み上がると帯の高さが伸びFAB・展開メニューと重なりうるが、エラーは15秒で自動消去される一過性の表示のため、右下スタックの対象外と判断している（`ErrorBar.tsx`のコメントに理由を明記）。**v3.92でToastのbottomを280pxから112px（PC）/128px（モバイル）へ下げたことで、ErrorBarの最大積み上げ状態（帯の高さ100px超）との位置関係がv3.90時点に近い値へ戻ったことを確認した**（Toastは84px→112pxで、ErrorBarとの相対関係は元々許容していたリスクの範囲内。この判断自体は変更していない）。

### 機械チェック（v3.91新設・v3.92で拡張）

`src/lib/layout/__tests__/bottomStack.test.ts`が、`bottomStack.ts`の定数から各要素の占有区間`[bottom, bottom+height)`を計算し、PC・モバイル×FABメニュー展開中／非展開中の4パターン全てで、**`ALLOWED_OVERLAPS`（理由付きの許容リスト。理由の説明が無いと登録できない＝`allowOverlap()`が例外を投げる）に載っていない重なりが無いこと**を検査する。**実装前にv3.90時点の値（PC：フッター/FAB・ショートカット/Toast、モバイル：ショートカット/Toast）に対して実際にこのロジックを走らせ、3件とも赤くなることを確認済み**（本Section冒頭の「根本原因」参照）。v3.92では追加で、`ALLOWED_OVERLAPS`の各ペアが実際に少なくとも1つのシナリオで重なっていること（＝不要な許容登録が残っていないこと）も検査する。

### 🔴 グランドルール：右下に要素を追加するときは必ずこのスタックに載せる

画面右下（PC）／画面下端（モバイル）に新しい固定要素（バッジ・ボタン・通知等）を追加するときは、bottom値を手書きせず、必ず`src/lib/layout/bottomStack.ts`のスタックへ新しい段として追加し、`bottomStack.test.ts`の重なり検査に組み込むこと。**重なりを許容したい場合は、bottom値の調整で無条件に回避しようとせず、まず「その要素は利用者が押したい操作ボタンか、隠れても実害の無い補助的な要素か」を判断し、後者同士の組み合わせに限って`ALLOWED_OVERLAPS`へ理由付きで登録すること。**
