## 60. 表示の圧縮方針：拡大して使う利用者への対応（v3.114・2026-09-18）

### 前提（これを取り違えると逆効果になる）

ブラウザの拡大は**CSS px を物理的に大きくする**＝ビューポートが CSS px 換算で縮む。
ツールバーやサイドバーの縦の占有は中身の高さで決まる固定量なので、**拡大すると
「固定占有 ÷ ビューポート高さ」の比率だけが上がり**、一覧に使える行数が激減する。

🔴 **拡大して使う人が欲しいのは「大きい文字」である。`fontSize` を下げる方向の圧縮は
利用者の目的そのものを潰すので、やってはいけない。** v3.114では `fontSize` を1箇所も
変更していない。

### 削ってよいもの／削ってはいけないもの

| 削ってよい（＝内容でない部分） | 削ってはいけない |
|---|---|
| 区切り線（`borderBottom`）と、それに付随して別々に乗る上下 padding | `fontSize` |
| 見出しラベル（意味はアイコン・ツールチップで代替できるもの） | タッチ/クリックの的中に効く横方向の padding（`td` の左右 `10px`）、モバイルカードの `12px`・`minHeight:52px`。※`td` の上下は v3.115 で山本さんの実機確認を受けて `6px`→`3px`（`ROW_TD_PADDING`）に詰めた。これ以上は詰めない |
| 段数（2段ツールバー → 1段＋ポップオーバー） | 情報そのもの（サブ文言は消さずに `title` へ移す） |
| 常時表示の必要がないボタン（ポップオーバーへ集約） | `data-tour-id`（ツアーが参照している） |
| ブロック要素として1行を占めている小さなボタン（インライン化） | `aria-label` |

### ツールバーをポップオーバーへ集約するときの型（v3.114で確立）

- 4つ以上のポップオーバーを作るなら、**共通コンポーネントを1つ作って使い回す**（Section 51 の
  教訓＝同じコードを複数箇所にコピペしない、がそのまま当てはまる）。
- **開いているメニューは単一 state（`openMenu: MenuId | null`）で持つ。** 各ポップオーバーが
  自前の boolean を持つと、同時に2つ開く状態を作れてしまう。
- 🔴 **ポップオーバーの中に `CustomSelect` を入れ子にしないこと。** `CustomSelect` は
  `createPortal(document.body)` する別のポップオーバーであり、親の「外側クリックで閉じる」
  判定がその Portal を外側と見なすため、**セレクトを開いた瞬間に親が閉じる**。選択肢が
  多くて検索が要る場合は、親パネルの中に素の `input` ＋リストを直接描画する。
- トリガーのラベルには**現在値を出す**（`▦ PJ別` `↕ 期日順`）。畳んだことで状態が見えなく
  なるのを防ぐ。**`sortKey` のように列見出しクリックでも変わる値は、取りうる値を全部
  ラベルに用意すること**（v3.114では7値。3値しか用意しないと「優先度順なのに ↕ 期日順 と
  表示される」嘘になる）。
- **検索欄を畳む場合は、検索語が入っている間は必ず開いたままにする。** 絞り込みが効いて
  いるのに入力欄が隠れていると、件数が減った理由が画面から分からなくなる。

### 未対応（効果を実機で確認してから判断する）

カンバン・ガント・ワークロード・ダッシュボードのツールバーには同じ方針を適用していない。
