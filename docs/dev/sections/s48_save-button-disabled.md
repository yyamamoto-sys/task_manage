## 48. クレーム「内容を変更したのに保存ボタンに🚫が出て押せない」への対応（必須・v3.93・2026-08-21）

### 調査結果：(A)/(B)/(C)分類

`TaskSidePanel.tsx`・`TaskEditModal.tsx`の操作可能なコントロールを全て洗い出し、(A) `form`/`sidebarForm`を変更しdirty経由で保存ボタンから保存される・(B) formを通らず即時保存される・(C) 画面上で変わるのに保存もされずdirtyにもならない、の3つに分類した。

| コントロール | 分類 | 備考 |
|---|---|---|
| タスク名・状態・優先度・担当者・プロジェクト・開始日/終了日・工数・メモ/コメント・タグ（モーダルのみ） | (A) | `computeFormDirty`（`taskEditPayload.ts`）が全フィールドを比較。既存の`taskEditPayload.test.ts`で網羅済みであることを確認済み |
| 階層モード（単独/子タスク/親タスクの切替ボタン） | (A)相当 | ボタン自体はローカルUI状態（`hierarchyMode`）の切替のみで、保存が要る変化は必ず`parent_task_id`（sidebarFormの一部）を経由する。モードだけ切り替えて中身を選ばない操作は「保存すべき差分が無い」ため、dirtyにならないのは正しい挙動（バグではない） |
| 親タスク選択・「子タスクを選ぶ」 | 親タスク選択=(A)（`parent_task_id`）／子タスクを選ぶ=(B)（`applyChildren`が対象タスクへ直接`saveTask`） | |
| 先行タスク・追加プロジェクト・タスクフォース（追加/解除） | (B) | `addTaskDependency`/`removeTaskDependency`等。join/unjoinで結果が即座に画面に見える設計（v3.87の線引き） |
| 削除 | 対象外 | 確認ダイアログ付きの独立操作 |

**(C)に該当するコントロールは見つからなかった。** `computeFormDirty`とTaskEditFormStateの全11フィールドの対応漏れも無い（新設した機械チェック`computeFormDirtyFieldCoverage.test.ts`で固定。実装前に`parent_task_id`の比較行を一時的に削除し、実際にテストが赤くなることを確認済み）。

**baselineの不正更新経路も見つからなかった。** `baselineFormRef`を書き換えている箇所は両ファイルとも「タスク切替時の初期化」「保存成功時」の2箇所のみで、Realtime更新や(B)系の即時保存操作からbaselineが書き換わる経路は無い。

### 実際の原因：(B)の即時保存が完全に無言だった

(C)が無い一方、(B)（タスクフォース・追加プロジェクト・先行タスク・子タスクの付け外し）の追加/解除は、既にDBへ保存済みであるにもかかわらず、成功時に一切のフィードバックが無かった（`applyChildren`のみtoastがあったが、TF/追加PJ/先行タスクの追加解除・`detachChild`は無言）。利用者が「変更した」と感じた操作の多くが実はこの(B)群であり、そのあと`form`側は無変更のまま保存ボタンにカーソルを合わせて🚫を見た、という体験が「変更したのに保存できない＝壊れている」の実体だったと判断した。

### 対応

1. **(B)群すべてに、既存の`SaveIndicator`（✓バッジ）を流用したフィードバックを追加した。** `flashImmediateSaved()`/`runImmediateSave()`（両ファイルにそれぞれ実装）が、即時保存が成功するたびにヘッダーの保存インジケータを1.5秒だけ「✓」表示にする。メイン保存（`handleSave`）が`"saving"`中なら上書きしない。エラーは呼び出し先（`appStore.ts`）が既に`showToast`で通知済みのため、ここでは何もしない。
2. **未変更時の保存ボタンの見せ方を「押せない禁止ボタン」から「保存済み」表示に変えた。**
   - `cursor: "not-allowed"` → 未変更時は`"default"`、保存中は`"wait"`（🚫を完全に廃止）
   - ラベル：未変更時は「保存」→「✓ 保存済み」
   - `title`：「変更はありません」→「保存済みです。変更するとこのボタンが押せるようになります。」
   - ボタン自体は引き続き`disabled`のまま（押せないこと自体は変えていない。「押せない理由の伝え方」だけを変えた）

### 機械チェック（新設）

`src/lib/__tests__/computeFormDirtyFieldCoverage.test.ts`：`TaskEditFormState`インターフェースのフィールド名集合と、`computeFormDirty`が`current.xxx`で参照しているフィールド名集合をソース走査で突き合わせ、完全一致することを検査する。将来フィールドを追加してcomputeFormDirty側の比較を足し忘れると（＝今回と同種の「画面上で変わったのに保存できない」バグの再発）、このテストが赤くなって気づける。
