# システム構成

plan-app を動かしている部品と、データ・処理の流れをまとめた記事です。IT 部門や開発の引き継ぎ先が、全体を把握するための入口として使えます。画面ごとの操作は他の記事を参照してください。

URL・プロジェクト識別子・鍵などの値は、この記事には載せていません（ガイドはアプリに同梱されるため）。それらは作成者が管理する別資料で扱います。

## 1. 全体構成

![利用者のブラウザ、Vercel、Supabase、Claude API の関係を示した全体構成図](./_img/architecture-overview.svg)

| 部品 | 役割 | データの有無 |
|---|---|---|
| 利用者のブラウザ | 画面（React）の実行。データの読み書きと AI 相談の呼び出し | 表示用に読み込んだ分のみ。表示設定・AI 相談履歴（最大10件）は端末に保存 |
| Vercel | 画面（静的ファイル）の配信。`main` への push で自動デプロイ | 業務データは持たない |
| Supabase の PostgreSQL | 業務データの保管。行レベルセキュリティ（RLS）で部署ごとに見える範囲を制限 | 業務データの正本 |
| Supabase の Auth | メールアドレスとパスワードによるログイン。ゲスト（サンプル閲覧）が AI 機能を使うときだけ、匿名でサインインする | ログイン情報 |
| Supabase の Realtime | データの変更（主要 11 表）と、自分宛てのアプリ内通知を、画面へ即時に反映（購読の内訳は第2章） | データは持たない |
| Supabase の Edge Functions | サーバー側の処理（AI 相談の中継・バックアップ・通知）。下表の 4 本 | 処理中のみ |
| Supabase の Storage | 日次バックアップの保管（現在使っているのは、専用の非公開バケット 1 つ） | バックアップファイル |
| Supabase の pg_cron | 定期処理の起動（第4章） | データは持たない |
| Claude API | AI 相談などの文章生成 | 送られた文面は Anthropic 側で処理 |

Edge Functions は次の 4 本です。

| 関数 | 役割 | 呼び出し元 |
|---|---|---|
| `ai-consult` | Claude API への中継。ログイン確認・利用回数の制限を行い、ブラウザからの呼び出し元を CORS で制限する | ブラウザ |
| `backup-daily` | 日次バックアップの実行 | pg_cron、管理画面の「今すぐ実行」 |
| `backup-export-urls` | バックアップのダウンロード用の期限付き URL（5分）を発行 | 管理画面（全社スーパー管理者のみ） |
| `push-reminders` | 期限通知・お知らせ・管理者向けのエラー通知の送信 | pg_cron、管理画面、送信者の画面、利用者本人の設定画面の「テスト送信」 |

## 2. 主な処理の流れ

### ログイン

1. ブラウザが Supabase の Auth に、メールアドレスとパスワードでログインする
2. ログイン中のメールアドレスと、アプリの利用者一覧（members）を突き合わせて本人を特定する
3. 特定できた場合は、前回の表示部署を復元して画面に入る。一覧に無い場合は「アクセスできません」の画面になる

Auth のアカウントと、アプリ上のメンバーは別のものです。一覧に追加されるまで、ログインできてもデータは見えません。

### タスクの読み書きとリアルタイム反映

1. 起動時に、必要なテーブルをまとめて読み込む。1 回に 1,000 行を超える表は、ページに分けて全件を取得する
2. 保存のタイミングは操作によって異なる。タスクの編集画面は保存ボタンで確定する。カンバンのドラッグ＆ドロップ、一覧のインライン編集、タスクフォース・プロジェクト・先行タスクの付け外しは、操作した時点で保存される。いずれもデータベースに書き込み、同じ行が先に更新されていた場合は、楽観ロックで検出して上書きを防ぐ
3. 主要な表の変更は Realtime で他の人の画面に届き、画面が最新の内容に取り直される。購読の内訳は下表のとおり
4. 保存のたびに変更履歴が記録される（保持 90 日）

| 購読 | 対象 |
|---|---|
| 主要 11 表の変更 | タスク、プロジェクト、ToDo、タスクとタスクフォース・プロジェクトの紐づけ、プロジェクトとタスクフォースの紐づけ、KR、タスクフォース、マイルストーン、メンバー、タスク間の依存 |
| タスク・プロジェクトの再取得 | タスクとプロジェクトの変更を検知すると、間隔をあけて全体を取り直す（上の購読とは別の購読） |
| 自分宛てのアプリ内通知 | ベルの未読数を即時に更新する。自分の行だけが届く |

業務データ（タスク・プロジェクトなど）の削除は論理削除で、物理的には消えません。変更履歴・エラー記録・実行記録などの記録類は、第4章の清掃で期間を過ぎたものが物理的に削除されます。タスクとタスクフォース・プロジェクトの紐づけや、タグとメンバーの紐づけの解除は、行を物理的に削除します。

### AI 相談

![ブラウザから Edge Function、Claude API を経由して回答が返り、利用者が確認して反映するまでの流れ](./_img/architecture-ai-flow.svg)

1. 画面側で、送るデータを組み立てる。コメント内のファイルパスとメールアドレスは伏せ字にする
2. ブラウザから Edge Function の `ai-consult` を呼ぶ。ここでログインと利用回数（1 分あたり）を確認する。ブラウザからの呼び出し元は CORS で制限する
3. `ai-consult` が Claude API を呼ぶ。API の鍵はサーバー側にのみあり、ブラウザには渡らない
4. 回答は提案として画面に出る。利用者が「反映する」を押すまで、データは変わらない
5. 使用量（機能別の回数・トークン）が記録され、設定の「AI使用量」で確認できる

送られる範囲は、[AI相談](./02_modes/consultation.md)を参照してください。AI 相談の質問と回答はサーバーに保存されません。

## 3. データの置き場所と見える範囲

見える範囲の制限は、画面の表示制限だけに頼らず、データベース側の RLS で行っています。データは部署（グループ）単位で分かれ、各行が所属する部署を持ちます。ログイン中のメンバーは、自分の所属部署（兼務を含む）の行だけを読み書きできます。全社スーパー管理者は、すべての部署を扱えます。

![部署ごとにデータが分かれ、メンバーは所属部署の分だけ見える様子を示した図](./_img/architecture-data-scope.svg)

| データ | 見える範囲 |
|---|---|
| プロジェクト・タスク・タスク間の依存 | プロジェクトが属する部署のメンバー |
| Objective・KR・TF・ToDo と、OKR の周辺 8 テーブル | 所属部署のメンバー |
| メンバー | 所属部署、兼務先、アクセスできるプロジェクトの参加者 |
| 個人 OKR | 本人のみ |
| 変更履歴 | 所属部署のメンバー |
| 通知・お知らせの宛先 | 本人（お知らせの送信状況は、送信者と全社スーパー管理者） |
| バックアップの管理表・エラー記録 | 全社スーパー管理者のみ |
| 部署の一覧・ローディングのヒント | 登録済みのメンバー（部署を問わない） |
| メンバータグ | 登録済みのメンバー（全社共通のマスタ） |

- メンバー情報の書き換えは、本人の行は本人、他の人の行はそのメンバーのホーム部署の管理者と全社スーパー管理者に限られます。部署管理者の権限が効くのはホーム部署だけで、兼務先では一般メンバーと同じです。招待用部署に所属する人の行は、その招待用部署が見える範囲にいる管理者も扱えます。部署の異動（ホーム部署の変更）は全社スーパー管理者だけが行えます
- プロジェクトを他部署の人に見せるには、プロジェクトの招待を使います。招待は 1 プロジェクトだけに有効です
- サンプル閲覧（ゲスト）は、業務データを読み書きしません。画面のサンプルデータを編集できますが、再読み込みで元に戻ります。AI 機能はすべて、回数を制限して使えます。AI を使うときだけ匿名でサインインし、Edge Function が回数とゲスト分の使用量をデータベースに記録します
- サイドバーの「表示部署」は、画面に出す範囲を絞る機能です。見えるデータの境界（RLS）とは別です

## 4. 定期処理

![pg_cron から起動される定期処理と、その結果の知らせ方を示した図](./_img/architecture-scheduled-jobs.svg)

時刻は日本時間（JST）です。起動は Supabase の pg_cron が行います。

| ジョブ名 | 頻度 | 内容 | 失敗時の知らせ方 |
|---|---|---|---|
| `backup-daily` | 毎日 3:00 | 全体と部署別の JSON を Storage に保存し、整合性を検証する | 全社スーパー管理者へアプリ内通知と Windows 通知。管理画面に警告バナー（24 時間成功がないと赤） |
| `push-reminders-am` | 平日 7:00〜8:30 の 30 分ごと（4 回） | Edge Function `push-reminders` を呼び、送信時刻を選んだ人へ期限リマインドを送る。土日と祝日はスキップ | 実行を毎回記録し、30 分以上前の予定回が無い・失敗のときは管理画面に警告バナー |
| `push-reminders-pm` | 平日 9:00〜19:30 の 30 分ごと（22 回） | 上と同じ関数を呼ぶ（時間帯の分け方だけが違う。合わせて 26 回） | 上と同じ |
| `cleanup-backup-runs` | 毎日 12:00 | バックアップの実行記録を 90 日で削除 | 専用の知らせなし |
| `cleanup-push-reminders` | 毎日 12:00 | アプリ内通知・送信記録・実行記録を 90 日で削除 | 専用の知らせなし |
| `cleanup-entity-change-logs` | 毎日 12:00 | 変更履歴を 90 日で削除 | 専用の知らせなし |
| `cleanup-client-error-logs` | 毎日 12:10 | 画面のエラー記録を 90 日で削除 | 専用の知らせなし |
| `cleanup-admin-change-logs` | 毎日 12:00 | 管理画面の変更履歴（`admin_change_logs`）を 14 日で削除。マイグレーション上は登録あり（本番の登録状況は未確認） | 専用の知らせなし |

- `backup-daily` は、実行の最後に、月曜のみ週次のまとめも通知します。保持は日次 14・週次 8・月次 12・四半期 8 世代です
- `push-reminders`（関数）は、同じ実行の中で、お知らせの未送信分の代行送信・期限前日の再通知・管理者向けのエラーのまとめ通知も行います
- 期限リマインドは、1 人 1 日 1 回です。同じ時刻に複数回起動しても二重には送られません
- 定期処理のうち、秘密の値の置き換えが要る `backup-daily` と `push-reminders-am`・`push-reminders-pm` の登録は、マイグレーションとは別に手で行います。`cleanup-entity-change-logs` と `cleanup-client-error-logs` は、マイグレーションの中で登録されます。`cleanup-backup-runs` と `cleanup-push-reminders` は秘密の値を使いませんが、登録の SQL は上の手で行うファイルに入っています

## 5. 更新と配布

| 対象 | 方法 |
|---|---|
| 画面 | `main` へ push すると、Vercel が自動でビルドして配信する |
| データベースの変更 | マイグレーションの SQL を、開発用 → 本番の順に手で適用する |
| Edge Function | 関数ごとに別のデプロイが必要。画面の配信とは連動しない |
| 定期処理 | 秘密の値の置き換えが要るものは手で登録する。それ以外はマイグレーションで登録される（上記のとおり） |

画面を先に配信すると、データベースの変更が未適用のため、新しい機能が動かないことがあります。マイグレーションが要る変更では、適用の順序が決まっています。順序は各リリースの記録（CHANGELOG）に書かれています。

### 版と再読み込みの通知

- 画面は、起動時・10 分ごと・タブに戻ったときに、配信中の版の情報を確認する
- 「この版より古い画面は不具合が出る」という最低限の版（`MIN_CLIENT_VERSION`）より古いときだけ、画面の上に再読み込みを促すバナーが出る
- 機能追加や見た目の変更だけの更新では、バナーは出ない。列の削除・RLS の変更・関数の入出力の非互換な変更を入れるときに、最低限の版を引き上げる
- 自動では再読み込みされない。編集中の内容を失わないように、利用者がボタンを押したときだけ再読み込みする

## 6. 外部サービス

| サービス | 役割 | 業務データの送信 |
|---|---|---|
| Vercel | 画面の配信 | なし |
| Supabase | 認証・データベース・Realtime・Edge Functions・Storage・pg_cron | あり（本体） |
| Anthropic（Claude API） | AI 相談などの文章生成 | AI 機能を操作したときのみ |
| GitHub | ソースコードの管理。Vercel の自動デプロイの起点 | なし |
| ブラウザのプッシュ通知の中継（Chrome は Google、Edge は Microsoft） | Windows 通知の配信 | 通知文面のみ（暗号化。中継側は読めない） |
| Google Fonts | 画面の書体の配信 | なし（ブラウザが直接取得） |
| esm.sh | Edge Function が読み込む部品（Supabase のライブラリ・祝日判定）の配信 | なし |
| npm レジストリ | Edge Function が読み込む部品（Windows 通知の送信ライブラリ `web-push`）の配信 | なし |
| Microsoft Teams | アプリをタブとして埋め込む場合の表示先。配信側の設定で、Teams のタブ埋め込みを許可している | なし（画面を表示する枠として使う） |

契約・アカウントの所在、データの保管場所、IT 部門への提出内容は、この記事の対象外です。
